# 通知解析置信度规则

版本：v1.3
更新时间：2026-05-02
适用范围：通知自动记账主链路

## 当前结论

通知自动记账只使用本地解析链路。系统先从通知标题和正文中抽取金额、方向、来源、商户和语义特征，再按账号会员状态选择置信度来源：

- 免费用户或会员状态未被服务器确认：使用 `local-rules-v1` 普通规则算法。
- 服务器确认的会员用户：使用 `local-linear-confidence-v1` 机器学习模型。

- `score >= 0.86`：高置信度，未命中重复时可自动入账。
- `0.62 <= score < 0.86`：中置信度，进入待确认。
- `score < 0.62`：低置信度，直接过滤。

疑似重复记录优先进入待确认，不直接自动入账。

## 模型方式

会员模型默认内置版本为 `local-linear-confidence-v1`。它不使用大模型、不依赖推理引擎，也不联网；模型形态是逻辑回归式线性评分：

1. 本地解析器生成结构化特征。
2. 如果本地已保存服务器全局模型，优先使用服务器下发的 `bias` 和 `feature weight`；否则使用内置冷启动权重。
3. 线性模型计算 `bias + Σ(feature * weight)`。
4. 通过 sigmoid 映射为 `0..1` 置信度。
5. 对高风险语义施加硬性上限，保护自动入账边界。

免费规则当前版本为 `local-rules-v1`。它只做固定规则加权和风险上限，不使用任何机器学习权重或模型数据。

## 特征来源

核心特征由 `core:data` 的本地解析器维护，包括：

- 来源先验：微信、支付宝、银行短信/银行 App 等可信来源会提供基础分。
- 金额信号：识别到明确金额和币种时提高可信度。
- 方向信号：支付、付款、转出、扣款偏支出；收款、到账、转入偏收入。
- 结构信号：账户尾号、交易对象、订单号、时间、动账关键词会提高可信度。
- 风险信号：营销、资讯、估值、浮盈、优惠券、待使用补贴等非交易语义会降低可信度。

## 风险上限

线性模型负责给出概率分数，但以下场景会额外限制最高分：

- 命中资产估值且没有结算证据：最高低置信度。
- 同时命中收入和支出方向：最高低置信度。
- 金额只是裸数字：不能进入高置信度。
- 营销消息且缺少交易场景证据：最高低置信度。

## 本地数据闭环

当前已经建立本地训练样本闭环：

1. 通知解析成功后，记录通知标题、正文、通知时间、模型特征快照、模型分数和流水线分流结果。
2. 待确认被直接确认时，样本标记为正样本。
3. 待确认被编辑后确认时，样本标记为编辑确认样本。
4. 待确认被忽略或标记误识别时，样本标记为负样本。
5. 自动入账记录被用户编辑或删除时，样本会补充对应反馈标签。

样本导出的 JSONL 包含 `rawTitle`、`rawText`、`rawPostedAt`、结构化特征、分数、分流和反馈标签，用于后续服务器训练。

## 账号与会员门禁

机器学习能力不能由本地默认开启，必须依赖服务器会员数据：

- 未登录：免费用户，只能使用 `local-rules-v1`。
- 已登录但服务器未确认会员：仍按免费用户处理。
- 服务器确认会员且下发模型权限：才允许使用机器学习置信度；客户端后续会优先拉取服务器发布的全局模型版本。
- 删除 App 后：本地缓存消失，用户需要重新手机号登录，再从服务器刷新会员状态。

## 会员全局云端学习骨架

当前已接入客户端和服务端技术骨架，真实训练任务和支付参数后续补充：

- 免费用户：只使用普通规则算法；登录且开启“用户改善计划”后，也会按周期上传通知原文样本，不拉取全局模型。
- 会员用户：可以拉取服务器全局模型；样本上传只由“用户改善计划”控制，不再和会员状态绑定。
- 字段纠错：用户编辑待确认项或已入账记录后，样本会带上 `parsed`、`corrected` 和 `changedFields`，用于后续训练金额选择、方向分类和商户抽取等专项模型。
- 全局模型：服务器综合所有用户上传样本训练并发布统一模型，客户端每 24 小时定时拉取最新版本，并把模型版本、权重、阈值、发布时间和有效期保存到本地。
- 模型生效：会员解析器会优先读取本地保存的服务器模型；如果没有模型、模型过期或权重为空，则回退 `local-linear-confidence-v1` 内置权重。
- 安全边界：服务器只能下发权重和更严格的风险阈值，不能放宽资产估值、方向冲突、金额弱证据和营销弱交易证据的客户端上限。
- 自动同步：会员状态在启动 / 回前台时刷新，并每 12 小时兜底刷新；训练样本持续累计并每 1 小时周期上传一次，不再因为待确认反馈创建加速上传任务。
- 设置页：提供手机号登录/注册、会员状态、年卡开通入口、用户改善计划开关和会员模型拉取入口。
- 仓储骨架：账号、支付、会员刷新、样本上传、全局模型拉取和本地模型仓库均已抽象成接口。

## 分流策略

1. 解析失败：返回失败结果，由通知处理状态记录错误。
2. 低置信度：标记为已过滤，不进入待确认。
3. 疑似重复：进入待确认，提示用户人工确认。
4. 高置信度且自动记账开启：写入账本。
5. 其他中置信度候选：进入待确认。
