# 客户端界面重构与体验升级方案（提案）

版本：v0.1  
日期：2026-04-14  
适用范围：Android 客户端界面层、导航层、轻量本地功能增强

## 1. 背景

当前项目的自动记账主链路、手动补记、待确认处理、设置与导出能力已经具备，测试也已通过，说明“业务逻辑可用”这一阶段目标已经完成。  
接下来需要解决的问题，不再是“能不能记账”，而是“用户是否愿意长期使用、是否能快速完成关键动作、是否觉得界面舒服和清晰”。

结合现有代码结构与当前界面截图，客户端的主要痛点集中在以下几个方面：

- 首页承载内容过多，总览、筛选、工作台、账单周期、洞察、趋势、分类、流水全部堆在一个长页面中。
- 底部导航中的“总览 / 账单”目前更像页内滚动定位，而不是明确的页面切换，信息架构不够清晰。
- 待确认页和设置页功能可用，但层级偏平，视觉表达较弱，缺少重点信息引导。
- 视觉语言已有暖色纸张感基础，但卡片类型、间距、强调层级、页面节奏还不统一。
- 当前交互更偏“功能堆叠”，还缺少“高频动作最短路径”的产品感。

## 2. 本轮目标

本轮改造建议以“保留原有逻辑，重做客户端体验层”为原则，目标如下：

- 把首页从“功能全集页”改造成“总览首页”。
- 把底部导航改成真正的页面切换，而不是页内滚动替代方案。
- 让账本页专注于搜索、筛选、日历、流水和分析浏览。
- 提升待确认页和设置页的信息层级、视觉完成度和操作效率。
- 在不依赖新后端的前提下，新增 2 到 3 个有产品感的本地功能。
- 尽量复用现有 ViewModel、Repository 与数据模型，避免破坏现有自动记账链路。

## 3. 改造原则

- 不改动自动记账、待确认、手动补记的核心业务判断逻辑。
- 优先改界面组织方式、导航关系、组件样式和本地状态扩展。
- 页面职责单一化，一个主页面只承载一个核心任务。
- 新功能优先选择“本地可实现、数据已有或容易扩展”的方向。
- 尽量保持当前测试可继续复用，新增改动补齐对应 UI 或 ViewModel 层测试。

## 4. 推荐信息架构

### 4.1 一级页面

Onboarding 完成后，进入一个统一的主壳层 `MainShell`，底部导航固定为 4 个一级页面：

1. 总览
2. 账本
3. 待确认
4. 设置

### 4.2 一级页面职责

#### 总览

定位：给用户一个“今天 / 本周 / 本月”的整体感知，不承载完整流水浏览。

建议保留内容：

- 本月收支与结余概览
- 待确认提醒卡片
- 快捷动作区
- 月预算或消费健康卡
- 最近 3 笔记录
- 一条重点洞察文案

建议移出内容：

- 完整流水列表
- 大段趋势图
- 分类分布完整列表
- 多账期横向卡片组

#### 账本

定位：账单浏览和查找主阵地。

建议承载内容：

- 搜索框
- 时间筛选
- 月历浏览
- 流水列表
- 趋势 / 分类分析分段内容

建议表现形式：

- 顶部保留“时间范围 + 搜索”
- 中部切换“流水 / 趋势 / 分类 / 日历”四个内容分段
- 不再把所有分析内容首屏堆叠展示

#### 待确认

定位：专门处理低置信度记录，不与总览页混杂。

建议承载内容：

- 顶部摘要：当前待确认数量、建议优先处理提示
- 卡片列表：确认入账、编辑后入账、忽略、标记误报
- 空状态优化：给出“当前无需处理”的正向反馈

#### 设置

定位：从“功能开关页”升级为“配置 + 数据工具页”。

建议承载内容：

- 自动记账相关能力开关
- 通知来源开关
- 数据保留策略
- 本地账本概览
- 导出工具
- 实验功能入口

### 4.3 二级页面

本轮建议保留并完善以下二级页面：

- 手动记账 / 编辑页
- 待确认编辑页
- 导出预览页或导出弹层
- 预算设置页
- 账单海报页（可选增强）

## 5. 导航改造方案

## 5.1 现状判断

当前 `LedgerScreen` 同时承担首页、工作台、分析页和账本列表页职责；底部栏中的“总览 / 账单”本质上通过滚动跳转到页面不同 section。

## 5.2 推荐方案

- 新建真正的底部 Tab 导航壳层。
- 每个 Tab 对应独立 route，并启用状态恢复。
- `FloatingActionButton` 在“总览 / 账本 / 待确认”页可见，在设置页隐藏。
- 总览页中的快捷入口点击后跳转到具体页面，而不是滚动到同页下方。
- 账本页内部分析内容采用二级分段切换，避免继续形成超长页面。

## 5.3 推荐路由结构

- `onboarding`
- `main/overview`
- `main/ledger`
- `main/pending`
- `main/settings`
- `entry/create`
- `entry/edit/{ledgerId}`
- `pending/resolve/{pendingId}`
- `budget/settings`
- `export/preview`
- `insight/poster`（可选）

## 6. 视觉改造方向

## 6.1 风格关键词

- 温暖纸感
- 轻量财务工具
- 简洁而不是空
- 数据清楚、重点突出

## 6.2 建议视觉语言

- 背景保持浅暖色系，但减少大面积混合色块。
- 强调色继续使用绿色作为“收入 / 安全 / 开启”语义主色。
- 辅助色采用沙金、墨灰、浅青，不再让页面同时出现过多同权重浅紫卡片。
- 统一卡片圆角、阴影、边框和内边距标准。
- 标题层级明确为：页面标题 > 模块标题 > 指标值 > 辅助说明。
- 空状态采用“说明 + 行动建议”的结构，而不是只放一句提示。

## 6.3 动效建议

- 底部 Tab 切换使用轻量过渡，不做复杂动画。
- 卡片首次进入页面采用小幅淡入上移。
- 月历切换采用水平过渡或渐进更新即可，避免大幅动效。

## 7. 页面级改版建议

### 7.1 总览页

推荐布局：

- 顶部问候与账本标题
- 本月收支总卡
- 待确认提醒横条
- 快捷动作 4 宫格
- 预算卡 / 消费健康卡
- 最近记录卡片

快捷动作建议：

- 记一笔
- 查看账本
- 待确认
- 导出 / 海报

这样改动后，总览页只负责“看重点、做高频动作”，不再承载完整分析。

### 7.2 账本页

推荐布局：

- 顶部标题栏：当前账期、搜索、筛选入口
- 分段切换：流水 / 趋势 / 分类 / 日历
- 主内容区域只显示当前分段内容
- 悬浮按钮固定为“记一笔”

流水分段：

- 搜索框
- 时间 chip
- 流水列表

趋势分段：

- 7 日 / 月度趋势
- 支出峰值提示
- 本周 / 本月对比

分类分段：

- 支出分类占比
- Top 分类
- 可扩展为收入来源分布

日历分段：

- 月份切换
- 日期格子
- 选中日期后显示当日摘要与流水

### 7.3 待确认页

推荐布局：

- 顶部摘要卡：待确认数量、处理建议
- 列表卡片强化“原因”和“建议分类”
- 主按钮为“确认入账”
- 次按钮为“编辑后入账”
- 危险或弱操作放到次级区域：忽略、标记误报

空状态建议：

- 展示“当前无需处理待确认记录”
- 提供“去账本看看”或“记一笔”入口

### 7.4 设置页

推荐布局分组：

- 记账能力
- 数据留存
- 来源管理
- 数据工具
- 实验室

说明：

- 开关类内容统一成样式一致的设置卡片
- 数据概览卡突出统计值，不只是纯文本堆叠
- 导出功能建议单独做成一个更完整的预览入口

## 8. 新增功能建议

本轮建议新增“一个强功能 + 一个轻功能 + 一个展示型功能”，既体现升级感，又控制复杂度。

### 8.1 功能 A：月预算与剩余额度

定位：强功能，强烈推荐纳入首批。

实现方式：

- 本地保存每月预算值
- 在总览页展示预算进度、剩余额度、超支提醒
- 在账本页趋势或分类分段中同步展示预算占用情况

优点：

- 与账本天然相关
- 不依赖后端
- 能显著增强总览页的产品价值

### 8.2 功能 B：快速记账动作面板

定位：轻功能，推荐纳入首批。

实现方式：

- 点击 FAB 后不直接进入单一表单，而是弹出动作面板
- 支持“支出”“收入”“套用模板”“从待确认补录”
- 保留原有记账编辑逻辑，只改变进入方式

优点：

- 提升操作效率
- 能让新增流程更有“产品完成度”

### 8.3 功能 C：月度账单海报 / 账单卡片

定位：展示型功能，推荐作为第二优先级增强。

实现方式：

- 基于现有本月收入、支出、结余、Top 分类生成一张简易账单卡
- 先做静态预览，不要求立即接入真实分享能力

优点：

- 界面表现力强
- 能让产品显得更完整
- 对底层逻辑影响很小

## 9. 技术实现建议

## 9.1 保留不动的层

- `core:data`
- `core:database`
- `service:notification`
- `service:automation`
- 现有大部分 Repository 读写逻辑
- 现有 EntryEditor / Pending 业务流转逻辑

## 9.2 重点调整的层

- `app/navigation`
- `feature/ledger`
- `feature/pending`
- `app/ui/SettingsScreen.kt`
- `app/viewmodel/LedgerViewModel.kt`
- `app/viewmodel/SettingsViewModel.kt`

## 9.3 推荐新增内容

- 新增 `OverviewScreen`
- 新增底部导航壳层 `MainShell`
- 新增预算本地状态与 ViewModel 映射
- 新增 FAB 动作面板组件
- 新增账单海报预览页或卡片组件

## 9.4 模块策略建议

为控制交付速度，本轮不强制新增独立 Gradle 模块。  
推荐优先在现有 `app` 或 `feature` 模块内完成页面重组；若后续总览页继续扩展，再考虑抽出 `feature:overview`。

## 10. 实施顺序

### 第一阶段：壳层与导航重组

- 建立真正的底部导航结构
- 把总览页与账本页拆开
- 保证现有入口和返回逻辑全部可用

### 第二阶段：账本页重做

- 精简首页负担
- 重构账本页为分段浏览
- 保留现有搜索、筛选、日历和流水逻辑

### 第三阶段：待确认与设置页优化

- 优化卡片层级、空状态和操作按钮
- 调整设置页分组和数据工具表现

### 第四阶段：新增功能接入

- 月预算
- 快速记账动作面板
- 月度账单海报（若时间允许）

### 第五阶段：验证与收尾

- 运行 `assembleDebug`
- 运行单元测试
- 检查主要导航路径和空状态

## 11. 验收标准

- 底部导航 4 个 Tab 均为真实页面切换。
- 总览页不再承载完整流水、趋势、分类全部内容。
- 账本页支持清晰切换流水、趋势、分类、日历视图。
- 记一笔、编辑、待确认处理原有逻辑不回退。
- 设置页结构更清楚，导出与数据概览更易理解。
- 至少新增 2 个用户可感知的新功能。
- 空账本状态、无待确认状态、已有数据状态都能正常显示。

## 12. 风险与边界

- 本轮不接入新后端，不引入真实云分析新能力。
- 本轮不改数据库主模型，预算等新数据优先走本地轻量存储。
- 若账单海报耗时超预期，可延期到第二批，不影响主导航和主页重构。
- 若需要控制工期，优先保证“导航重构 + 总览拆分 + 月预算”，其余功能按优先级递延。

## 13. 推荐采纳版本

建议采用以下组合进入实施：

### 必做

- 真正的底部导航重构
- 总览页与账本页拆分
- 账本页分段化
- 待确认页与设置页视觉优化

### 推荐增强

- 月预算与剩余额度
- 快速记账动作面板

### 有余力再做

- 月度账单海报

## 14. 对当前项目的价值

如果按此方案执行，项目会从“可用的 AI 自动记账 Demo”明显提升为“结构完整、体验更像正式产品的记账 App”。  
同时，因为本方案主要改动 UI 层、导航层和少量本地状态层，所以整体风险可控，适合在现有代码基础上继续推进。
