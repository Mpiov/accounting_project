# Android 基础框架落地计划（仅客户端）

## Summary
- 目标：在空仓库内搭建可运行的 Android MVP 骨架，覆盖“权限向导 -> 账本首页 -> 待确认页”主路径。
- 技术栈：Kotlin、Jetpack Compose、Hilt、Coroutines + Flow、Room + SQLCipher、JUnit5 + MockK。
- 架构策略：中等多模块 + 本地 Mock 可运行 + 云接口占位（不接真实后端）。
- 验收标准：`./gradlew assembleDebug testDebugUnitTest ktlintCheck` 通过，应用可安装并跑通 3 个页面与本地事件流。

## Implementation Changes
1. 工程与构建骨架
- 创建 Gradle Kotlin DSL 工程，统一版本目录与插件管理。
- 设置 `applicationId = com.autobook.cn`，`minSdk = 29`，`targetSdk/compileSdk = 35`。
- 配置基础质量门禁：ktlint、单测任务、debug/release 构建配置。

2. 模块划分（中等多模块）
- `app`：应用入口、导航、依赖装配、权限状态总控。
- `core:model`：领域模型与结果类型。
- `core:database`：Room + SQLCipher、DAO、本地数据源。
- `core:data`：Repository 实现、本地/云路由编排。
- `core:network`：云端 API 占位接口与 DTO（仅契约，不落真实调用）。
- `core:common`：通用工具、错误类型、时间/金额格式化。
- `feature:onboarding`：权限向导与能力开关页。
- `feature:ledger`：账本首页与基础统计卡片（空数据态 + 示例数据态）。
- `feature:pending`：待确认列表与确认/忽略动作。
- `service:notification`：`NotificationListenerService` 骨架与事件入库。
- `service:automation`：无障碍与截屏协调器骨架（仅流程占位，不做激进自动化）。

3. 公共接口与类型（先定契约）
- 领域类型：`NotificationEvent`、`TransactionCandidate`、`LedgerEntry`、`PendingEntry`、`ParseConfidence`。
- 关键接口：`NotificationIngestor`、`CaptureCoordinator`、`OcrEngine`、`TransactionExtractor`、`ModelRouter`、`LedgerRepository`、`PendingRepository`。
- 路由约束：`ModelRouter` 默认本地优先，云端接口仅在开关开启时可选调用。
- 结果模型：统一 `Success/RetryableFailure/TerminalFailure`，支持可追溯字段（来源、解析路径、模型版本占位）。

4. 可运行流程（骨架阶段）
- 首次启动进入权限向导，缺失关键权限时阻断自动化能力但不阻断手动记账页面。
- 通知服务接收事件后写入 `notification_events`，通过本地 Mock 解析器生成候选交易。
- 置信度阈值规则：高置信度入账本，低置信度进入待确认列表。
- 账本首页展示最近流水、当日收支占位统计；待确认页支持“确认入账/忽略”。

5. 工程基线与文档
- 新增 `README`：本地运行、模块职责、权限说明、后续接后端步骤。
- 新增最小 CI（GitHub Actions）：构建、格式检查、单元测试。
- 约定配置项：`cloud_analysis_enabled=false`、`auto_accounting_enabled=true`（可在设置页改）。

## Test Plan
- 单元测试：`ModelRouter` 本地优先策略、阈值分流逻辑、Repository 基本读写。
- 单元测试：`TransactionExtractor` Mock 输入输出映射，失败重试标记。
- 仪器测试：权限向导跳转逻辑、首页/待确认页渲染与关键交互。
- 集成验证：通知事件入库 -> 解析 -> 入账/待确认完整链路（使用 Fake OCR/Fake Cloud API）。
- CI 通过标准：assemble + ktlint + unit tests 全绿。

## Assumptions
- 当前阶段只做 Android 客户端骨架，不创建后端工程；你之前给的“Java”偏好保留给后端阶段决策。
- 不接真实 OCR 与真实 LLM，只实现接口和 Fake 实现，确保后续可平滑替换。
- 默认中国区、CNY、简体中文文案；iOS 暂不纳入本次骨架。
