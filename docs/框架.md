# Android 当前架构总览

版本：v1.2  
更新时间：2026-04-15  
适用范围：当前 `main` 分支代码现状说明

## 1. 文档用途

这份文档用于给后续开发对话、代码评审和问题排查提供“当前实现状态”的统一上下文。  
如果后续讨论与本文冲突，以 `main` 分支代码为准，再回头修正文档。

## 2. 当前实现结论

- 项目已不再是“仅客户端骨架”，而是已经具备可运行的 Android 自动记账 MVP。
- 当前主链路为：通知监听 -> 本地解析 -> 本地语义增强 / 本地 LLM 复核 -> 自动入账 / 待确认 / 过滤。
- 默认仍然坚持“本地优先、云端关闭、低风险优先”的策略。
- 当前没有真实后端工程；`core:network` 仍以接口占位和未来扩展为主。

## 3. 模块结构

### 3.1 应用与功能模块

- `app`
  - 应用入口、导航、页面装配、ViewModel 挂载。
  - 包含设置页、手动编辑页、调试页、导出预览等客户端整合逻辑。
- `feature:onboarding`
  - 首次引导、权限状态展示、能力启用入口。
- `feature:ledger`
  - 账本首页、时间筛选、日历模式、列表与统计展示。
- `feature:pending`
  - 中置信度记录与疑似重复记录的待确认列表及确认处理。

### 3.2 核心能力模块

- `core:model`
  - 领域模型、设置模型、通知状态、交易候选、本地模型描述等公共类型。
- `core:common`
  - 通用工具与公共基础能力。
- `core:database`
  - Room 数据库、DAO 与本地账本持久化。
- `core:data`
  - 仓储实现、通知处理流水线、图片识别预留能力、本地模型仓储、启发式分析与本地 LLM 调度。
- `core:network`
  - 未来云端分析接口的占位层，目前不承担真实线上能力。
- `core:llm`
  - 基于 `llama.cpp + GGUF` 的本地推理运行时与 JNI / CMake 封装。

### 3.3 系统服务模块

- `service:notification`
  - `NotificationListenerService` 实现、通知提取、调试追踪与事件入库入口。
- `service:automation`
  - `AccessibilityService`、当前页面截图与截屏协作能力。

## 4. 当前主链路

### 4.1 通知入账链路

1. `service:notification` 监听系统通知并抽取基础文本。
2. 通知事件写入本地数据库，带上来源应用、去重键、处理状态等信息。
3. `core:data` 中的本地解析器先基于通知文本做规则与启发式抽取。
4. 若开启本地语义增强，则对中间结果执行额外复核；当前既有启发式增强，也已接入真正的 `llama.cpp` 端侧运行时。
5. 根据置信度与重复判断，结果进入账本、待确认列表或直接过滤。

### 4.2 用户可见链路

- Onboarding：用于解释权限、能力和默认策略。
- Ledger：用于查看账本、时间筛选、按日历回看流水。
- Pending：用于确认中置信度候选与疑似重复记录。
- Settings：用于切换自动记账、云端分析、图片导入 OCR / 截图开关、本地语义增强、本地模型选择与下载、留存天数、来源白名单、CSV 导出预览，以及启动截图快捷记账常驻入口。
- Entry Editor：用于手动新增、编辑、应用快捷模板。

## 5. 本地模型与原生能力

### 5.1 当前实现

- 本地模型运行时已经接入 `core:llm` 模块。
- `third_party/llama.cpp` 以 Git submodule 的方式管理，不直接把第三方源码散落进业务目录。
- 当前推荐模型为 `Qwen3 1.7B GGUF`。
- 模型文件通过运行时下载到应用私有目录，不打包进 APK。
- 当前设置页可以查看模型状态、选择模型并触发下载。

### 5.2 当前边界

- 本地 LLM 已可运行，但仍属于“增强链路”，不是唯一解析手段。
- 云端分析默认关闭，且当前没有接入真实生产云模型。
- 如果本地 LLM 或原生库不可用，系统会回退到启发式本地分析，而不是让主流程完全不可用。

## 6. 当前默认策略

- `autoAccountingEnabled = true`
- `cloudAnalysisEnabled = false`
- `captureEnabled = false`
- `ocrEnabled = false`
- `localLlmConfidenceBoostEnabled = false`
- `notificationRetentionDays = 30`
- `screenshotRetentionDays = 7`
- 默认启用来源：微信、支付宝、银行卡短信

这些配置目前由 `DataStore` 持久化，设置页可直接修改。

## 7. 当前已完成的客户端增强

- 账本首页支持“今日 / 本月 / 全部 / 日历”多种时间浏览模式。
- 日历模式支持按天查看流水和日级收支概览。
- 手动记账页支持快捷模板。
- 设置页支持本地账本概览、CSV 预览导出、一键复制。
- 设置页支持本地模型状态查看、模型下载与刷新。
- 图片导入已接入真实选图入口，并支持按设置在“云端大模型代理链路”和“ML Kit OCR + 本地 Qwen”之间切换。
- 当前云端图片链路的业务命名已统一为“云端大模型”，不再把具体模型名直接暴露到领域层和 UI；当前实际配置模型为 `gemini-3-flash-preview`。
- 当前页面截图记账已支持通过设置页启动常驻通知入口；用户点击整条常驻通知即可触发截图，不再依赖通知内额外按钮。
- 截图分析完成后，如果产生待确认记录，不会强制跳转到待确认页；当前通过总览页提醒卡和底部导航 badge 提示用户后续处理。
- 截图链路的多候选后处理会按以下顺序执行：
  - 先剔除已退款 / 已退还 / 已撤销 / 已取消候选
  - 再按“分钟级时间 + 金额 + 方向”做批内去重；缺少时间时不做强去重
  - 再与本地账本做历史判重；只有“分钟级时间 + 金额 + 方向”一致时才强判重
  - 如果候选缺少时间，但本地已存在同金额同方向记录，且候选本身是中高置信度，则降级到待确认而不是直接过滤
  - 最后从剩余候选中按置信度、时间完整度和金额完整度择优
- Debug 构建下支持通知注入调试服务，便于真机联调通知解析链路。

## 8. 当前未完成或仍是占位的部分

- 真实后端与真实云模型调用。
- 过期通知与截图的自动清理 Job。
- 完整的数据导出 / 删除 / 注销闭环。
- 更细粒度的错误观测、线上埋点和崩溃上报。
- iOS 对等能力。
