# 数据留存策略（当前工程版）

版本：v1.1  
更新时间：2026-04-14  
适用范围：当前 `main` 分支实现

## 1. 当前默认策略

- 原始通知文本：默认保留 30 天
- 截图引用与截图文件：默认保留 7 天
- 结构化账本记录：长期保存
- 云端分析：默认关闭
- 截图分析：默认关闭
- OCR：默认关闭
- 本地语义增强 / 本地 LLM：默认关闭

## 2. 当前已经落地的留存控制

### 2.1 设置项已落地

当前设置页已经支持：

- 调整通知留存天数
- 调整截图留存天数
- 开关云端分析
- 开关截图分析
- 开关 OCR
- 开关本地语义增强

### 2.2 数据结构已准备

当前通知事件模型已经具备以下留存治理相关字段：

- 处理状态
- 重试次数
- 错误信息
- 截图引用

这意味着后续要补后台清理任务时，数据结构层面已经可支撑。

## 3. 当前实际存储位置

### 3.1 通知与账本数据

- 通知事件、账本记录、待确认记录存储在本地数据库。
- 当前数据库使用普通 Room / SQLite 持久化，不再额外做本地加密。

### 3.2 截图文件

- 截图文件保存到应用私有目录。
- 当前 `ScreenshotStorage` 使用专门目录保存 OCR 截图引用。
- 截图不会默认出端，也不会打包进 APK。

### 3.3 本地模型文件

- 本地模型通过运行时下载到应用私有目录。
- 模型文件不属于通知 / 截图留存天数管理范围。
- 当前模型文件会持续保留，直到用户替换、清理或卸载应用。

## 4. 当前尚未完成的留存治理

以下部分目前还没有落地，需要后续补齐：

- 定时清理过期通知
- 定时清理过期截图文件
- 手动一键清理历史通知与截图
- 用户注销后的彻底清空
- 数据导出后的生命周期管理说明

## 5. 当前对后续开发的约束

- 不应把截图改成长期无限保留。
- 不应在未补充文档和清理能力前，把更多高敏感原始数据落地到本地。
- 若后续接入真实云端分析，需要补充“云端是否保留原文 / OCR 文本 / 推理结果”的独立策略。

## 6. 当前建议的后续补齐顺序

1. 增加基于留存天数的本地清理任务。
2. 在设置页增加“立即清理过期数据”入口。
3. 补充导出、删除、注销的数据治理闭环。
4. 在隐私说明中明确通知、截图和模型文件的留存口径。

## 7. 对后续对话的提示

如果后续新对话问“截图会不会一直留着”“模型文件存哪”“清理能力做到哪一步了”，优先以本文为准。  
如果代码实现与本文不一致，应先修正文档。
