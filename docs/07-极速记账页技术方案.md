# 极速记账页技术方案

## 1. 目标

- 在不改造现有完整编辑页职责的前提下，新增一条“3 秒记账”的高频录入链路。
- 用户点击右下角加号后，进入独立的极速记账页。
- 用户点击具体分类后，立即进入金额输入状态，并用自定义数字键盘快速完成录入。
- 保留“继续补充更多字段”的能力，但不让它拖慢主链路。

## 2. 非目标

- 本阶段不替换现有完整编辑页。
- 本阶段不把图片导入、候选切换、待确认处理并入极速记账页。
- 本阶段不做旧版本兼容分支。
- 本阶段不直接进入 UI 实现，只完成设计与拆分方案。

## 4. 核心判断

### 4.1 不直接改造现有完整编辑页

- 原因：
  - 现有页面职责过重。
  - 存在三种模式复用。
  - 含图片导入、模板、删除、订单号等低频能力。
  - 交互节奏不适合“点分类后立刻输入金额”。

### 4.2 新增独立 `QuickEntry` 路由

- 推荐新增一条独立路由，例如 `entry/quick`。
- `entry/create` 继续服务完整编辑页。
- `entry/edit/{ledgerId}` 和 `pending/resolve/{pendingId}` 保持不变。

### 4.3 抽取共用保存能力，而不是复用整个 `EntryEditorViewModel`

- 推荐把“创建一笔手动记账记录”的校验与 `LedgerEntry` 映射抽成独立共用层。
- 完整编辑页和极速页都调用这层。
- 这样可以避免：
  - 快速页被商户必填等完整页规则拖累。
  - 两套页面重复拼接 `LedgerEntry`。
  - 后续修改保存字段时改两遍。

## 5. 目标产品形态

### 5.1 主链路

1. 用户点击右下角加号。
2. 直接进入极速记账页。
3. 页面默认显示上次使用的方向，若没有历史则默认 `支出`。
4. 用户点击某个分类。
5. 分类立即高亮，金额区进入输入状态。
6. 自定义数字键盘立即可用。
7. 用户输入金额，点“完成”。
8. 直接保存并返回上一页。

### 5.2 次级链路

- 用户需要补更多信息时，点“更多”进入完整编辑页。
- 需要保留当前已填内容，不允许跳转后丢失：
  - 方向
  - 分类
  - 金额
  - 备注
  - 时间
  - 可选的商户

## 6. 页面职责边界

### 6.1 极速记账页负责

- 收支方向切换
- 分类宫格选择
- 金额输入
- 轻备注
- 快速日期选择
- 直接保存
- 跳转完整编辑页继续补充

### 6.2 完整编辑页继续负责

- 编辑已有账单
- 待确认记录入账
- 图片导入与候选切换
- 模板预填
- 商户 / 对方编辑
- 分类手动改写
- 订单号编辑
- 删除已有账单
- 完整错误提示与人工确认流程

## 7. 路由方案

### 7.1 新增目标

- 新增 `AutobookDestination.QuickEntry`
- 推荐路由形式：

```text
entry/quick?direction={direction}
```

### 7.2 首版参数

- 首版只带 `direction` 即可。
- 分类、金额、备注、时间这类页面内状态，先放在 `QuickEntryViewModel` 中维护。

### 7.3 从极速页跳完整页

- 完整编辑页现有路由参数只支持 `direction` 和 `templateId`。
- 因此如果要实现“带着半成品数据跳完整页”，需要扩展 `EntryCreate` 路由或增加共享中转状态。

### 7.4 推荐实现

- `QuickEntry` 自己维护录入状态。
- 点击“更多”时，使用以下两种方案之一：

#### 方案 A：扩展 `EntryCreate` 路由参数

- 增加：
  - `category`
  - `amount`
  - `note`
  - `timestamp`
  - 可选 `merchant`

优点：

- 路由显式。
- 页面重建后仍能恢复。

缺点：

- 参数增多。
- 需要注意编码与可读性。

#### 方案 B：引入共享草稿仓库

- 新增一个仅用于界面跳转过渡的 `QuickEntryDraftRepository` 或 `SavedStateHandle` 共享通道。

优点：

- 路由简洁。
- 复杂字段不用拼 URL。

缺点：

- 状态链路隐式。
- 调试成本更高。

### 7.5 推荐结论

- 首版推荐 `方案 A`。
- 原因：
  - 当前项目路由简单直接。
  - 首版只需要传少量基础字段。
  - 不必额外引入新的全局草稿依赖。

## 8. 状态模型方案

### 8.1 推荐新增 `QuickEntryUiState`

建议字段：

- `direction: MoneyDirection`
- `selectedCategory: String?`
- `amountInput: String`
- `note: String`
- `entryTimestamp: Long`
- `merchant: String`
- `isAmountInputActive: Boolean`
- `canSubmit: Boolean`
- `errorMessage: String?`
- `finished: Boolean`

### 8.2 交互状态规则

- 页面初始进入时：
  - `selectedCategory = null`
  - `amountInput = ""`
  - `isAmountInputActive = false`
- 用户点分类后：
  - 设置 `selectedCategory`
  - `isAmountInputActive = true`
- 用户切换方向后：
  - 分类池切换
  - 若当前分类不属于新方向，清空 `selectedCategory`
  - 金额不自动清空
- `canSubmit` 判断：
  - 方向有效
  - 已选分类
  - 金额大于 0

## 9. 保存模型方案

### 9.1 推荐新增共用请求模型

建议新增一个创建请求模型，例如：

- `ManualEntryDraft`

建议字段：

- `amount`
- `direction`
- `category`
- `merchant`
- `note`
- `timestamp`
- `channel`
- `traceSource`
- `tracePath`
- `traceModelVersion`
- `editedManually`

### 9.2 推荐新增共用创建能力

建议新增一个共用创建方法或用例，例如：

- `CreateManualLedgerEntryUseCase`

职责：

- 校验草稿最小合法性
- 统一把草稿映射成 `LedgerEntry`
- 调用 `LedgerRepository.add()`

### 9.3 校验规则拆分

完整编辑页当前规则：

- 金额必填
- 商户必填
- 方向必选

极速页不建议直接复用“商户必填”规则。

推荐拆成两套最小规则：

- 完整编辑页规则：
  - 金额必填
  - 商户必填
  - 方向必选
- 极速记账页规则：
  - 金额必填
  - 分类必选
  - 方向必选
  - 商户可选

## 10. 分类方案

### 10.1 设计原则

- 分类是极速页主入口，不再使用“模板”概念作为首层入口。
- 分类名称要稳定，便于后续统计与图表聚合。
- 数量首版不要过多，避免宫格过重。

### 10.2 首版建议分类池

#### 支出

- 餐饮
- 购物
- 日用
- 交通
- 蔬菜
- 水果
- 零食
- 娱乐
- 通讯
- 服饰
- 住房
- 居家
- 医疗
- 学习
- 礼金
- 宠物

#### 收入

- 工资
- 奖金
- 报销
- 兼职
- 理财
- 红包
- 收款
- 转账收入

### 10.3 与当前模板的关系

- 当前模板仍保留给完整编辑页。
- 极速记账页不再展示模板芯片。
- 后续可以考虑把模板数据迁移成“完整编辑页预填数据源”，分类宫格使用独立配置。

## 11. 交互约束

### 11.1 默认方向

- 进入极速页时优先恢复上次使用方向。
- 如果没有历史，则默认 `支出`。

### 11.2 分类点击行为

- 点击分类立即高亮。
- 若当前没有金额输入状态，则进入金额输入状态。
- 再次点击同一分类，不取消选中，避免误操作。

### 11.3 金额输入行为

- 使用自定义数字键盘。
- 金额格式支持：
  - 整数
  - 一位小数
  - 两位小数
- 不允许多个小数点。
- 不允许前导零导致异常格式。

### 11.4 保存行为

- 点击“完成”后立即保存。
- 保存成功：
  - 关闭极速页
  - 返回上一页
- 保存失败：
  - 停留当前页
  - 显示轻错误提示

### 11.5 备注行为

- 备注保持轻量。
- 默认只展示一行入口。
- 首版不做多段复杂输入。

### 11.6 时间行为

- 首版支持：
  - 今天
  - 昨天
  - 选择日期
- 若不主动改时间，默认使用当前时间戳。

## 13. 分阶段实施

### 阶段 1：完成架构落位

- 新增 `QuickEntry` 路由
- 新增 `QuickEntryViewModel`
- 抽取共用保存逻辑
- 保留 `EntryCreate` 原样

### 阶段 2：接通极速页主链路

- `FAB` 改为直接进入极速记账页
- 总览页和待确认页的“新建”入口视需要统一到极速页
- 支持分类选择与快速保存

### 阶段 3：补充完整编辑衔接

- 从极速页进入完整编辑页
- 保留方向、分类、金额、备注、时间

### 阶段 4：增强体验

- 记忆上次方向
- 记忆高频分类排序
- 细化日期快捷入口
- 分类配置可扩展

## 14. 风险点

### 14.1 校验规则耦合风险

- 现有完整编辑页要求商户必填。
- 若直接复用当前保存逻辑，会破坏极速页的“只选分类和金额即可提交”目标。

### 14.2 路由参数膨胀风险

- 若极速页跳完整页要透传太多字段，`EntryCreate` 路由会变复杂。
- 首版应控制字段数量，优先传最关键字段。

### 14.3 两套录入入口认知风险

- 如果 `FAB` 走极速页，而总览空态仍走完整页，用户会感知不一致。
- 需要明确哪些入口统一切换，哪些入口保留完整页。

### 14.4 模板与分类重复风险

- 若极速页继续沿用模板，容易和分类宫格形成重复入口。
- 因此建议两者职责彻底分离。

## 15. 最终建议

- 采用“新增独立极速记账页 + 保留完整编辑页”的双轨方案。
- 采用“抽共用保存逻辑，不复用完整编辑页 ViewModel”的技术方案。
- `FAB` 最终目标是直接进入极速记账页，不再先弹两按钮面板。
- 完整编辑页继续承载复杂场景，极速页只服务高频新建。

## 16. 开工前确认项

- 是否接受 `FAB` 直接进入极速页，而不是先弹支出 / 收入面板。
- 是否首版就统一总览页空态与待确认页空态的新建入口。
- 是否接受极速页首版把“商户”降为可选字段。
- 是否接受完整编辑页路由扩参，以承接极速页半成品数据。
