# 子任务2：中国区合规与隐私方案（工程落地版）

版本：v1.0  
日期：2026-04-12  
适用范围：面向中国大陆用户的自动记账 App（Android 优先）

说明：本文是产品与工程落地清单，不替代正式法律意见。上线前应由法务进行最终审阅。

## 2. 合规目标与原则

- 目的限定：仅为“自动记账”处理必要数据，不做与记账无关扩展用途。
- 最小必要：权限、字段、存储时长、传输范围均按最小化设计。
- 透明可控：所有敏感处理动作有明确告知、可撤回、可暂停。
- 默认安全：本地加密、传输加密、脱敏日志、分级访问。
- 可审计：关键处理活动可追溯，支持审计与举证。

## 3. 数据分类分级（本产品）

### 3.1 数据项清单与分级

| 级别 | 典型数据项 | 处理要求 |
| --- | --- | --- |
| A 级（高敏感） | 通知正文中的金额、商户、订单号、支付渠道；截图图像；用户账本记录 | 单独同意、强加密、短留存、严格访问控制 |
| B 级（中敏感） | 设备标识、应用版本、错误日志（脱敏后） | 最小化采集、按需留存、脱敏展示 |
| C 级（低敏感） | 通用运行指标（性能统计、匿名崩溃信息） | 匿名化处理、仅用于稳定性优化 |

### 3.2 敏感个人信息判定

按照《个人信息保护法》关于敏感个人信息定义，涉及金融账户、交易流水等内容时应按敏感个人信息处理，执行“单独同意 + 强保护 + 严限制”。

## 4. 处理活动合法性基础与同意机制

### 4.1 同意体系（建议）

- 首次启动：展示隐私政策摘要 + 完整版链接 + 处理目的说明。
- 分项授权：通知读取、无障碍自动化、截屏分析、云端模型分析均独立开关，默认“关闭云端分析”。
- 权限说明：每个开关都要说明用途、必要性、不开启的影响。
- 撤回机制：设置页可随时关闭任一能力，关闭后立即停止新增采集。

### 4.2 不得捆绑

依据“必要个人信息范围”规定，实用工具类基本功能不应强制索取非必要信息。  
工程要求：拒绝自动化权限时仍需保留手动记账能力。

## 5. 权限最小化与产品交互约束

### 5.1 权限矩阵

| 权限 | 目的 | 约束 |
| --- | --- | --- |
| 通知读取 | 识别交易通知 | 仅处理用户明确选择的来源 App；可随时关闭 |
| 无障碍能力 | 必要时下拉通知栏 | 仅执行声明动作，不做其他自动化操作 |
| MediaProjection 截屏 | 补充 OCR 信息 | 仅在文本不足时触发，默认关闭，用户可见可停 |

### 5.2 交互要求（强制）

- 每个权限单独说明“不开启会失去什么能力”。
- 任一权限拒绝不得导致 App 退出或不可用。
- 权限关闭后，后台任务不再继续调用对应系统能力。

## 6. 本地/云端模型合规策略

### 6.1 默认路由策略

- 默认本地模型优先（可离线解析的尽量不出端）。
- 国内云模型作为补充（优先选择境内地域、境内部署）。
- 境外云模型为可选高风险路径，默认关闭，需单独同意与专项评估。

### 6.2 跨境传输判定与路径

- 场景 A：仅本地模型  
  不发生个人信息出境。
- 场景 B：境内云模型（数据中心在中国大陆）  
  原则上不构成出境，但仍需最小化与合同约束。
- 场景 C：境外云模型或跨境链路  
  需按《促进和规范数据跨境流动规定》与《个人信息出境认证办法》判断路径（豁免/标准合同/认证/安全评估），并完成单独同意与影响评估。

## 7. 个人信息保护影响评估（PIPIA）与记录

以下处理活动在上线前必须完成 PIPIA 并留存报告：

- 处理敏感个人信息（交易流水、截图）。
- 委托第三方模型服务商处理个人信息。
- 向境外提供个人信息（如启用境外云模型）。
- 对个人权益有重大影响的自动化决策流程（如自动入账导致账本变化）。

留存建议：评估报告与处理记录至少保留 3 年。

## 8. 存储、留存与删除策略（建议默认值）

- 原始通知文本：默认本地加密保存 30 天（用于纠错与追溯），可由用户改为更短。
- 原始截图：默认本地加密保存 7 天，云端默认不保存。
- 结构化账本：按用户持续使用需求保存，提供导出与删除能力。
- 训练样本回流：默认关闭；开启时需再次征求同意并去标识化。

## 9. 用户权利实现清单（产品必须提供）

- 查询与复制个人信息（账单导出、原始记录导出）。
- 更正与补充（手工编辑交易字段）。
- 删除（单笔删除、批量删除、账户注销后一键清空）。
- 撤回同意（权限开关与云分析开关可即时生效）。
- 解释说明（自动入账结果可查看“来源与判定依据”）。

## 10. 第三方与供应链治理

- 建立 SDK 清单：名称、用途、采集字段、共享对象、隐私政策链接。
- 禁用“与当前功能无关”的 SDK/埋点。
- 与模型供应商签署数据处理协议（用途限制、保密、删除、审计权）。
- 对外包/合作方实施最小权限访问和定期审计。

## 11. 安全控制基线（工程实现）

- 传输：TLS 1.2+，证书校验与域名白名单。
- 存储：端侧数据库加密，密钥托管于系统安全区。
- 日志：订单号、账号、手机号等强脱敏后写日志。
- 访问控制：后台管理最小权限、操作审计、双人复核高风险操作。
- 漏洞治理：发布前进行静态扫描、依赖漏洞扫描、渗透测试。

## 12. 事件响应机制

- 建立数据安全事件分级（一般/严重/重大）。
- 明确 24x7 处置链路：发现 -> 研判 -> 遏制 -> 修复 -> 复盘。
- 涉及个人信息泄露时，按法规要求及时告知用户与监管报告（依法执行）。

## 13. 上线前检查清单（可直接执行）

1. 法务检查  
隐私政策、用户协议、第三方共享清单完成审阅；权限用途文案与实际行为一致。
2. 产品检查  
拒绝任意权限后手动记账主路径可用；“自动记账总开关”“云端分析开关”默认值正确。
3. 客户端检查  
权限只在使用时申请；关闭权限后相关任务即时停止且无残留上传。
4. 服务端检查  
数据库字段分级与加密策略生效；审计日志可追溯到“谁在何时处理了什么数据”。
5. 安全检查  
高危漏洞清零；中危风险有缓解与上线豁免记录；备份、恢复、应急演练通过。
6. 合规运营检查  
App 备案状态可核验；跨境数据路径（如有）完成对应机制与文档归档。

## 14. 两个关键决策（建议立即定版）

- 决策 1：默认本地模型优先，云端模型默认关闭（用户手动开启）。
- 决策 2：自动化权限与核心手动记账彻底解耦，避免“不同意就不能用”。
