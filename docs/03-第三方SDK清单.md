# 第三方 SDK 与第三方组件清单

版本：v1.2  
更新时间：2026-04-15  
适用范围：当前 `main` 分支工程依赖现状

## 1. 文档用途

这份文档用于回答两个问题：

- 当前项目到底接了哪些第三方运行时依赖？
- 哪些只是占位、测试或源码级第三方组件，而不是实际联网 SDK？

## 2. 当前已接入的运行时依赖

| 名称 | 类别 | 当前用途 | 数据处理说明 |
| --- | --- | --- | --- |
| Jetpack Compose / AndroidX | UI 框架 | 页面、导航、生命周期、测试支持 | 本地框架依赖，不直接采集业务数据 |
| Hilt | 依赖注入 | 模块装配与运行时注入 | 本地运行时依赖，不直接采集业务数据 |
| Room | 本地数据库 | 存储通知事件、账本记录、待确认记录 | 数据存储在端侧 |
| DataStore | 设置存储 | 保存开关、白名单、留存天数、模型选择等 | 数据保存在端侧 |
| ML Kit Text Recognition Chinese | 端内 OCR | 对图片导入内容 Uri 与本地截图执行文字识别 | 当前仅在端内执行，不默认上云 |
| Retrofit / OkHttp | 网络基础库 | 云端大模型图片分析代理与未来接口扩展准备 | 当前主要用于图片导入 / 截图场景的自研代理请求 |
| Material Components | UI 组件 | Android Material 风格支持 | 不处理业务数据 |

## 3. 当前已接入的第三方源码 / 原生组件

| 名称 | 形式 | 当前用途 | 说明 |
| --- | --- | --- | --- |
| `third_party/llama.cpp` | Git submodule | 端侧本地 LLM 推理底座 | 通过 `core:llm` 模块接入 JNI 与 CMake，不是云 SDK |

补充说明：

- 当前推荐模型为 `Qwen3 1.7B GGUF`。
- 模型文件不是仓库依赖，也不会打包进 APK，而是运行时下载到应用私有目录。

## 6. 当前与隐私最相关的依赖说明

### 6.1 ML Kit OCR

- 当前不再参与通知自动记账主链路。
- 当前主要用于“用户主动上传图片记账”场景，也可复用于后续截图辅助链路。
- 当前作为端内 OCR 使用，不应默认上传截图到第三方服务。

### 6.2 llama.cpp

- 当前属于端侧运行时，不是托管云服务。
- 只在本地模型文件已准备好且用户开启对应增强开关时才参与链路。
- 当前实现目标是“本地语义增强”，不是把所有通知都交给本地 LLM 强制处理。

### 6.3 Retrofit / OkHttp

- 当前除了承担未来接口层准备，也已经用于“用户主动触发的图片导入 / 截图分析”云端大模型代理请求。
- 通知自动记账主链路虽然有云端分析开关，但当前 `main` 分支仍没有落真实通知云解析能力。

## 7. 新增依赖的准入规则

后续新增任意第三方 SDK 或第三方源代码组件时，必须补充以下内容：

1. 名称与版本来源
2. 用途
3. 是否处理个人信息
4. 是否出端
5. 用户是否可关闭
6. 是否需要补充隐私政策和合规说明
